# 上海温度

原生 macOS 应用，固定上海及杭州，另有江浙沪区域地图、摄氏度、Asia/Shanghai 时区。包含 7 天、15 天、30 天趋势及前后 30 天四个上海组件，另有杭州前后 30 天组件，均为标准中号桌面小组件；高温为珊瑚橙线，低温为冰蓝线，透明背景，无地区、单位或样式配置。

v0.2.2 新增浅灰透明玻璃应用图标，保留暖金色太阳、珍珠白云和淡色温度曲线。设计参考 Bas Milius 的 Meteocons（MIT），版权说明随应用一起打包。图标已提供全部 macOS 标准尺寸，构建时检查 AppIcon.icns 是否实际生成。

## GitHub 在线构建

本工程不要求使用者本机安装 Xcode。GitHub Actions 的 `macos-26` 运行器负责：

1. 检查工程文件引用和扩展嵌入关系。
2. 执行 Swift 数据解码、集合平均、缓存、跨天、失败回退和请求合并测试。
3. 用完整 Xcode 编译 arm64 + x86_64 应用及 WidgetKit 扩展。
4. 先对扩展、再对应用进行 ad-hoc 签名，并检查签名、双架构与扩展信息。
5. 生成 ZIP、DMG、SHA256 校验文件，作为 Actions 构建产物保存。
6. 版本标签（例如 `v0.2.7`）构建成功后发布预览版 GitHub Release。

初次上传运行：

```bash
bash scripts/publish-github.sh --public --release
```

这个命令会在当前登录的 GitHub 账户下创建 **公开仓库 `ShanghaiTemperature`**，上传此目录的源码，并推送 `v0.2.7` 标签。若未登录，会进入 GitHub 官方登录流程。脚本会使用 GitHub noreply 邮箱提交；不包含私人证书、API Key、个人文件或其他项目源码。已存在的同名仓库不会被覆盖。GitHub CLI 需提前安装（本机已检测到 `gh`）。

日常推送 main 运行构建并保留产物；发布新版本则推送新的 `vX.Y.Z` 标签。Release 默认为预览版，不宣称完成了实机验收。不要重复覆盖旧标签。

公开仓库使用 GitHub 标准托管运行器，不需要自行填写 Apple 密钥或搬用 Sticky 的 secrets。正式 Developer ID 签名和 Apple 公证可后续单独配置；当前预览版未公证，macOS 可能提示运行限制。不得以“签名检查通过”冒充 Gatekeeper、公证或桌面组件注册通过。

## 已实现的运行逻辑

- 7 天、15 天共用一次 15 天常规预报请求；同一组件进程内并发请求合并。
- 30 天使用 ECMWF EC46 51 成员，逐日最高温、最低温分别取集合平均，注明“长期趋势，仅供参考”。
- 前后 30 天使用独立常规接口请求（`past_days=15&forecast_days=15`），保留过去 15 天与今天起 15 天，标记“今天”。历史部分为归档模型数据，不标为气象站实测。
- 正常数据缓存 3 小时；上海午夜会请求刷新。失败后 30 分钟重试，不密集轮询。
- 缓存原子写入本地 Application Support。应用和扩展分别使用自己的沙箱缓存；原有五个组件共享扩展缓存；地图组件使用独立缓存。无需 App Group 权限。
- 缓存最多保留为可用数据 48 小时。预报组件跨天剔除已过日期，前后 30 天组件按今天往前 15 天至今天往后 14 天的窗口滚动；缺少未来日期时标注有效天数，不补造温度。
- 无有效缓存时显示“暂无有效预报”；样例仅用于组件库预览和占位，真实运行失败不会退回样例。
- 后续时间线预先安排了整点、缓存过期和跨日状态，避免系统延迟网络刷新时仍把过期数据当新数据。
- 请求超时、HTTP 错误、空值、摄氏度单位、时区、日期连续性、成员完整性、高低温大小关系均有检查。

WidgetKit 最终决定实际刷新时机，3 小时是请求策略，不保证定时精确唤醒。应用无需常驻；主窗口只有添加说明、数据源获取状态和来源链接。

## 数据源

- 固定坐标：上海 31.2304, 121.4737；杭州 30.2741, 120.1551。
- 常规接口：https://api.open-meteo.com/v1/forecast
- 延伸期接口：https://seasonal-api.open-meteo.com/v1/seasonal
- 参数：`temperature_unit=celsius`、`timezone=Asia/Shanghai`，延伸期使用 `models=ecmwf_ec46`。
- 来源：https://open-meteo.com/ ，数据许可 CC BY 4.0。
- 个人非商业用途适用 Open-Meteo 免费接口要求；商业发布前需重新核对服务授权。EC46 未做当地偏差订正，不应理解成与短期预报同等精度。

接口已在 2026-11-16 返回上海完整 15 天和 30 天数据，温度单位、日期与 51 成员数据完整性已核对。接口可用性不代表应用已经完成编译和桌面验收。

## 工程结构

- `App/`：极简主窗口。
- `Shared/WeatherModel.swift`：上海日期、固定周期、快照状态、组件库样例。
- `Shared/WeatherService.swift`：固定接口、51 成员解码、请求合并、缓存与刷新策略。
- `Shared/TemperatureChartView.swift`：共用高低温曲线与无数据状态。
- `Widgets/`：五个中号曲线组件及一个大号体感地图组件。
- `Tests/`：由 Swift Package 驱动的真实 Swift 测试。
- `.github/workflows/build.yml`：在线测试、构建、产物保存与预览发布。
- `scripts/`：工程生成、结构检查、构建打包、公开仓库上传脚本。

应用名仍为“上海温度”，新增第 5 个中号组件“杭州 · 前后30天”：过去 15 天及今起 15 天，合计 30 天。沿用透明背景、高低温颜色、日期刻度和今天标记。上海前后 30 天组件的底部也改为“过去15天 · 今起15天”，移除界面中的“模型数据”文字，数据来源与计算方式不变。

## v0.2.7 江浙沪体感地图

新增第6个大号组件“江浙沪 · 体感地图”，App名和前5个组件不变。温度面跨行政边界连续插值，边缘柔化，显示温度区间跨度不超过3°C。只标注指定10个小写地点名，不显示城市温度。节气日期按上海时间：普通日期显示前后两个节气，交节当天仅显示该节气；2025—2027年使用香港天文台发布的日期，其余年份为近似太阳黄经回退。

完整的2015—2025年100点、9,643,200个地点小时ERA5样本内置在扩展中一份，气温/湿度/10米风速数值无损保存，二进制总计57,859,200字节。原始下载数据、日志和本地分析输出不随源码提交。天气数据由Open-Meteo提供（CC BY 4.0）；地图几何来自Natural Earth，public domain。

主界面“本地计算地图体感”默认关闭。关闭使用API体感字段；开启使用本地阴凉处公式。两种模式均用同一口径比较当天与历史，缓存互不混用。网络历史体感首次分批准备，可能需要多次系统刷新后完成；本地模式使用内置历史数据。正常请求每小时刷新，准备中请求2分钟重试、限流30分钟、其他失败15分钟；实际时间由WidgetKit决定。缓存最长有效48小时，并标明旧缓存。

冷暖提示比较历史同期均值；近期进程比较14天同一时段曲线，方向不一致、历史年份不足或结果不稳定时不显示提前/推迟。不得将它解释为正式入季日期或已证明的气候变化。模型差异和代表性仍需实机/回放检查。

发布前本机可运行 `python3 scripts/check-weather-endpoints.py` 验证小规模真实API连接。CI执行资源检查、完整历史校验、极端与小温差日期回放、Swift测试、双架构编译和扩展资源/签名检查。通过CI不等于已经验证了实际地图排版、开关跨进程同步或系统刷新行为，下载安装后需逐项验收。
